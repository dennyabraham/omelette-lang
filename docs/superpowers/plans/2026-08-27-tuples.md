# Tuples Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add tuple syntax — `(x, y)` expressions and `(a, b)` patterns (arity ≥ 2) — as parser sugar for fixed-arity arrays.

**Architecture:** Option A — tuples reuse the existing `array` expression node and `array_pat` pattern node, so there is **no new codegen and no new pattern kind**. Only the parser changes: a comma after the first parenthesized expression makes an `array` node; `(` in pattern position makes an `array_pat`. `(e)` stays grouping.

**Tech Stack:** Pure Lua (LuaJIT + Lua 5.4 in CI); `omelette.parser` / `omelette.compiler`; `spec/support/harness.lua`.

## Global Constraints

- Runs on both LuaJIT and Lua 5.4 (CI matrix).
- No new AST nodes and no codegen change — tuples produce `array` (expression, field `items`) and `array_pat` (pattern, field `elems`), which already have codegen.
- `(e)` with no comma remains grouping (returns the inner expression) — existing parenthesized forms `(match …)`, `(if …)`, `(fn …)` must be unaffected.
- No trailing comma in a tuple literal.
- `compiler.eval(src)` → module table; `compiler.compile(src)` → `lua, nil`; `parser.parse_expr_string(src)` → single-expression AST. Harness: `require("spec.support.harness")` (`h.describe/it/eq/truthy`). Run: `luajit spec/run.lua`.

- [ ] **Step 1: Write the failing tests**

Create `spec/tuple_spec.lua`:

```lua
local h = require("spec.support.harness")
local compiler = require("omelette.compiler")
local function eval(src) return assert(compiler.eval(src)) end

h.describe("tuples", function()
  h.it("builds and matches a 2-tuple", function()
    h.eq(eval("pub let r = match (1, 2) with | (a, b) -> a * 10 + b").r, 12)
  end)
  h.it("builds and matches a 3-tuple", function()
    h.eq(eval("pub let r = match (1, 2, 3) with | (a, b, c) -> a + b + c").r, 6)
  end)
  h.it("a tuple pattern can have a literal slot", function()
    h.eq(eval("pub let r = match (0, 5) with | (0, y) -> y | (x, y) -> x + y").r, 5)
    h.eq(eval("pub let r = match (3, 5) with | (0, y) -> y | (x, y) -> x + y").r, 8)
  end)
  h.it("grouping still returns the inner value (no comma)", function()
    h.eq(eval("pub let r = (1 + 2) * 3").r, 9)
  end)
  h.it("nests", function()
    h.eq(eval("pub let r = match ((1, 2), 3) with | ((a, b), c) -> a + b + c").r, 6)
  end)
  h.it("supports multiple-return via a tuple, matched out", function()
    h.eq(eval([[
let minmax a b = if a < b then (a, b) else (b, a)
pub let r = match minmax(5, 2) with | (lo, hi) -> hi - lo
]]).r, 3)
  end)
  h.it("a tuple expression parses to an `array` node", function()
    local e = assert(require("omelette.parser").parse_expr_string("(1, 2)"))
    h.eq(e.kind, "array")
    h.eq(#e.items, 2)
  end)
  h.it("the emitted Lua loads", function()
    local lua = assert(compiler.compile("pub let r = (1, 2, 3)"))
    local load_fn = loadstring or load
    h.truthy((load_fn(lua)))
  end)
end)
```

- [ ] **Step 3: Add tuple expressions to `parse_primary`**

In `omelette/parser.lua`, find the `(` grouping branch in `parse_primary`:

```lua
  if self:at("punct", "(") then
    self:next()
    -- parse_expr_or_form so a parenthesized form (match/if/fn) is usable as a
    -- primary, hence in ANY expression position: (match … ) |> f, [ (match …) | … ],
    -- match (match …) with …, 1 + (if c then a else b), etc.
    local e = self:parse_expr_or_form()
    self:expect("punct", ")")
    return e
  end
```

Replace it with a version that makes a tuple when a comma follows (grouping otherwise):

```lua
  if self:at("punct", "(") then
    self:next()
    -- parse_expr_or_form so a parenthesized form (match/if/fn) is usable as a primary.
    local first = self:parse_expr_or_form()
    if self:at("punct", ",") then
      -- tuple: fixed-arity array sugar `(e1, e2, …)`
      local items = { first }
      while self:accept_comma() do
        items[#items + 1] = self:parse_expr()
      end
      self:expect("punct", ")")
      return { kind = "array", items = items, line = t.line, col = t.col }
    end
    self:expect("punct", ")")
    return first
  end
```

- [ ] **Step 4: Add tuple patterns to `parse_pattern`**

In `omelette/parser.lua`, in `Parser:parse_pattern()`, add a `(` branch (place it next to the array-pattern `[` branch). A `(` in pattern position is a tuple pattern (patterns have no grouping form):

```lua
  if self:at("punct", "(") then
    self:next()
    local elems = {}
    repeat elems[#elems + 1] = self:parse_pattern() until not self:accept_comma()
    self:expect("punct", ")")
    return { kind = "array_pat", elems = elems }
  end
```
